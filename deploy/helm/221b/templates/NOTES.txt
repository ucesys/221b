{{- if include "b221.movingTag" . }}
That tag moves with every build: each helm upgrade restarts the console on its latest build, and

  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "b221.fullname" . }} | grep -m1 serving

shows the commit it was built from. Pin one build with --set image.tag=sha-<commit> or --set image.digest=sha256:<digest>.

Upgrade with --reset-then-reuse-values to keep your settings and take the chart's new defaults.
{{- $svc := include "b221.fullname" . }}
{{- if eq .Values.service.type "LoadBalancer" }}

It is exposed with a LoadBalancer Service on port {{ .Values.service.port }}. Find its address with

  kubectl -n {{ .Release.Namespace }} get svc {{ $svc }} -w

and browse to http://<that address>:{{ .Values.service.port }}. Until a load balancer controller gives it an
address, it also answers on every node's port shown under PORT(S), after the colon.
{{- else if eq .Values.service.type "NodePort" }}

It is exposed on every node at the port shown after the colon under PORT(S):

  kubectl -n {{ .Release.Namespace }} get svc {{ $svc }}
{{- end }}
{{- with .Values.service.externalIPs }}

It also answers on port {{ $.Values.service.port }} at {{ join ", " . }}.
{{- end }}
{{- if .Values.ingress.enabled }}

It is published through an Ingress at {{ if .Values.ingress.tls.enabled }}https{{ else }}http{{ end }}://{{ .Values.ingress.host }}{{ .Values.ingress.path }}
{{- if not .Values.ingress.tls.enabled }} without TLS: sessions travel in the clear; set ingress.tls.enabled=true with a certificate.{{ end }}
{{- else if eq .Values.service.type "ClusterIP" }}

Open it with a port-forward:

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ $svc }} 8080:{{ .Values.service.port }}

then browse to http://localhost:8080.

{{- if eq .Values.auth.mode "oidc" }}

People sign in with {{ default "the OIDC provider" .Values.auth.oidc.providerName }} at {{ .Values.auth.oidc.issuer }}; register the callback
{{ if .Values.auth.oidc.redirectURL }}{{ .Values.auth.oidc.redirectURL }}{{ else }}https://<the console's host>/signin/callback{{ end }} with the client {{ .Values.auth.oidc.clientID }}.
{{- else if eq .Values.auth.mode "local" }}

People sign in with the console's own accounts (auth.local.users){{ if not .Values.auth.local.users }}{{ if not .Values.auth.local.existingSecret }}, of which there are none yet:
nobody can sign in until you add some. Make a password hash with

  kubectl run hash --rm -it --restart=Never --image={{ include "b221.image" . }} -- hash-password

then add the account and upgrade:

  helm upgrade {{ .Release.Name }} <chart> -n {{ .Release.Namespace }} --reset-then-reuse-values \
    --set 'auth.local.users[0].email=you@example.com' --set 'auth.local.users[0].passwordHash=<hash>' \
    --set 'auth.admins[0]=you@example.com'

Or sign in with your identity provider instead: auth.mode=oidc with auth.oidc.issuer, clientID and clientSecret.{{ end }}{{ end }}
{{- else }}

Sign-in is off (auth.mode=none): anyone who can reach the console sees the cluster and is an administrator.
Set auth.mode=oidc or auth.mode=local before exposing it.
{{- end }}
{{- if or .Values.auth.admins .Values.auth.adminGroups }}

Administrators, who manage connections and the settings: {{ join ", " (concat .Values.auth.admins .Values.auth.adminGroups) }}.
{{- else if ne .Values.auth.mode "none" }}

No administrators are named (auth.admins, auth.adminGroups): everyone who signs in is a viewer, and nobody
can change the settings or manage connections until one is.
{{- end }}

Every sign-in, sign-out and change is in the audit log: one JSON line on the console's standard output,

  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "b221.fullname" . }} | grep '"action"'
{{- with .Values.audit.webhook.url }}

and POSTed to {{ . }}.
{{- end }}

The refresh rate in its Settings applies to everyone and is kept in the ConfigMap {{ include "b221.fullname" . }}.
{{- if eq .Values.connections.store "secrets" }}

Other clusters are added from the cluster menu by an administrator. Each connection is kept as a Secret
named {{ include "b221.fullname" . }}-cluster-<id> in this namespace, which the console may manage Secrets in:
keep it in a namespace of its own. List them with

  kubectl -n {{ .Release.Namespace }} get secrets -l app.kubernetes.io/component=cluster-connection
{{- else }}

Connections to other clusters are kept in memory (connections.store=memory) and lost on restart.
{{- end }}
{{- if .Values.secrets.read }}

Secrets are read (secrets.read), so each namespace lists its Secrets by key name and size and the Helm tab
reads release records; a Secret's values never leave the server. Set secrets.read=false to grant no access
to Secrets at all, which also hides the Helm tab.
{{- else }}

Secrets are not read (secrets.read=false): the ClusterRole grants nothing on Secrets, namespaces list no
Secrets and there is no Helm tab, since Helm keeps its release records in Secrets.
{{- end }}

Check what it is allowed to read:

  kubectl auth can-i --list --as=system:serviceaccount:{{ .Release.Namespace }}:{{ include "b221.serviceAccountName" . }}
